## 修改内容

- `server/config.mts`、`app.js`：识别小红书两个分享域名，保持域名边界校验，拒绝伪造后缀。
- `server/xiaohongshu.mts`：优先解析公开页面的对应作品 JSON；支持移动端 `noteData.data.noteData`、桌面端 `note.noteDetailMap[id].note`。仅将字符串外的 `undefined` 转为 JSON null，不执行脚本。普通视频的 `imageList` 只用作封面；图文逐图保留；实况必须有每张图片自己的明确标记，动态地址缺失不会凭空生成。作品 ID 必须匹配；保护媒体不解析。已知官方 CDN 的 HTTP 地址仅升级为同地址 HTTPS，随后仍经过原有媒体、DNS、重定向校验。
- `server/instagram.mts`：解析公开页面 JSON 中 `xig_polaris_media.if_not_gated_logged_out`，精确匹配 shortcode；依据 `media_type` 分类，保留全部 `carousel_media` 与每个视频的 `video_versions`。登录门控或缺少真实资源时明确失败，不将封面降格成图集。未调用猜测的接口或签名参数。
- `server/parse.mts`：Instagram、小红书与抖音都优先使用公开页面适配器，失败后保留现有第三方回退。
- `app.js`：非 JSON 的本站 API 响应区分预览登录重定向、401/403、429、5xx，避免一律指责路由；不显示 HTML 原文或上游凭证。
- `index.html`、`README.md`：更新解析路径说明，保留原界面和交互。
- `tests/frontend.test.mts`、`tests/xhs-public.test.mts`、`tests/instagram-public.test.mts`：新增域名同步、公开页面实际结构、图集顺序、普通视频封面、实况关联、作品身份、登录门控、禁止执行脚本、重定向、回退和完整下载回归。

## 抖音限制的评估

这条短链已证明可在浏览器展开到对应 `/note/` 长链接，当前问题发生在服务器获取作品数据阶段，而非作品 ID 提取。公开分享页面与桌面页面本次均未提供可解析的完整作品对象，原服务也超时；不能据此声称作品已删除或短链无效。参考开源项目关于公开分享页和图文路径的说明，核对了公开 `share/slides` 页面，但本样本同样没有作品数据（[上游讨论](https://github.com/Evil0ctal/Douyin_TikTok_Download_API/issues/394)）。没有引入要求生成安全签名或复制登录 Cookie 的实现，也没有在没有接口契约的情况下编造参数。

本次新增公开页面适配器不需要 API 密钥或 VPS，也没有新增依赖或媒体域名允许项。沿用 Preview 已配置的 `MEDIA_TOKEN_SECRET` 和 `MEDIA_ALLOWED_HOSTS=dl.tiktokio.com`。生产环境仍未设置本次运行密钥，不应直接合并。

验收完成并取得明确生产发布指令后，再配置生产环境变量、合并 PR、检查构建、复验生产站。正式入口仍为原来的 Netlify 域名。

## 发现并修复

1. 原服务的小红书旧示例返回 `status:true`，但作品 ID 为空，只有一个站点落地页图片。新增 `POST_IDENTITY_MISSING` 检查：旧协议必须有非空 `noteId/note_id`，或有可识别的嵌套作品；无身份的站点图片不再进入媒体列表。版本化独立适配器协议仍按明确的 `items` 分类处理。
2. 无封面时，标题容器曾被网格挤进 160px 一列。新增无封面布局状态和长词换行，保留原深色 UI 与媒体分区。
3. 超时文案细分到“第三方解析服务请求超时”和“媒体资源校验超时”，保持原错误码，避免把不同阶段混为一个网络错误。

新增三项回归覆盖无作品身份的落地页、嵌套作品身份及超时阶段。总计 **99 项离线测试通过**；类型/语法、构建和五个 Function 入口打包检查通过。真实源站验收范围见下表，不能用离线测试替代。

## 真实平台结果与待验项

| 平台/功能 | 当前结果 | 边界 |
|---|---|---|
| X 单视频 | 高清媒体响应、1280×720 浏览器元数据、前端完整接收流程通过 | 磁盘保存未独立验证；多视频、图片和真实高清拒绝回退仍需新样本 |
| 抖音给定短链 | 仍跳首页；备用解析请求超时；明确失败，无假成功 | 尚未恢复此短链；需要近期有效短链/长链区分旧链接问题与平台限制 |
| Instagram README 旧示例 | 上游明确返回失败 | 旧帖子当前是否仍可公开访问未确认，需要近期链接 |
| TikTok README 示例 | 原先被域名校验拒绝；精确放行后出现超时 | 后续以部署后的分阶段文案定位；不能认定已恢复 |
| 小红书 README 旧示例 | 上游只有空作品 ID 和落地页图片 | 新版应明确拒绝；需要有效单图、多图、视频、实况样本 |
| 手机布局 | 未计为通过 | 浏览器视口接口请求 390px，但实际 CSS 视口仍为 1728px；已撤下误标手机尺寸的截图并恢复默认视口 |

下载验收限制：两种受支持的下载事件接口都未捕获 Chrome 下载事件；页面本身确认 Blob 完整接收。打开 `chrome://downloads/` 被浏览器安全策略拒绝，未使用其他方式绕过访问浏览器下载历史的限制。磁盘文件需由用户手动确认；媒体响应与预览结果不等于磁盘落盘已验证。

当前不应合并上线。先用近期、公开且有权保存的作品补齐有效链接、图集、多段视频、实况和手机浏览器测试。所有平台只有封面、上游失败或资源不可用时都应继续保持明确失败。生产配置应在 Preview 验收完成、用户确认发布后再设置。

## 新证据

用户新分享 `https://v.douyin.com/72vABkYfa3k/` 可展开到图文作品 `7678244347540995018`。公开分享页没有对应作品媒体对象，仍不能直接解析，但这不等于作品失效。现有解析服务后来用作品长链约 2.72 秒返回了 19 个候选地址，说明它存在波动，不能仅凭此前超时判断为完全不可用。

这 19 项使用 `dl.snapcdn.app`；样本 HEAD 返回音频和 JPEG MIME，无重定向，图片 GET 前缀确认 JPEG 文件头。实际 Netlify 长链调用也返回 `BLOCKED_HOST`，所以媒体域名缺少允许项是一个已确认的阻塞，而非 CORS 或前端下载按钮问题。

核对原 SDK 主仓库的 `src/index.ts` 和 `src/Defaults/site.ts`，其 Douyin 实现仍调用同一服务，升级 SDK 不会自动换成其他解析来源（[源码](https://github.com/hostinger-bot/btch-downloader/blob/main/src/index.ts)、[配置](https://github.com/hostinger-bot/btch-downloader/blob/main/src/Defaults/site.ts)）。

## 实施

1. `server/douyin.mts` 保留从官方输入、逐跳重定向确认的 ID 与 note/video 路径；在公开页面解析失败后，把去掉追踪参数的作品长链交给备用服务。未知作品 ID 的首页短链保持明确失败，不凭空生成 ID。
2. `server/parse.mts` 使用这个已确认的长链作为抖音回退输入，避免备用服务重复处理短链跳转；其他平台不变。
3. `server/provider.mts` 仅抖音请求上限调整为 12 秒，仍受整次解析 45 秒预算约束，没有无限等待。
4. Preview 的 `MEDIA_ALLOWED_HOSTS` 改为 `dl.tiktokio.com,dl.snapcdn.app`。只增加这个精确主机，没有放开通配符。生产上下文仍为空；HTTPS、端口、每跳域名、连接时 DNS、公网地址、MIME、文件头和体积检查继续有效。
5. `server/media.mts`、`server/network.mts` 及公开页面适配器修复等待上游取消清理可能永不结束的问题：立即发起并捕获清理错误，但不等待清理确认才返回已校验资源、下一重定向或传输错误。回归测试用一个永不完成的 cancel Promise 复现风险；该风险可能拖长响应，但不能据此断言此前所有 504 都由它导致。
6. 媒体候选仅在超时或网络故障时最多重试一次，且每次重新完整校验；403、过期、格式与大小错误不重试、不伪装成功。
7. 前端把尚未确认类型的失败条目放入“未确认资源”，不再归入“视频”。保留原深色界面和逐项错误卡片。
